# AI co-design round 2: the program places the board, and the project remembers

Direction from the maintainer (2026-11-09): people get EasyEDA Pro's hand-editing experience; models design without filling their context, and the program does the routine work. Round 1 gave the schematic that side (`new_circuit`, placement by connectivity, routed wires, compact answers). The board still has none of it: `src/engine/autoplace.ts` only packs unplaced parts next to their block without overlap, the positions are not written, the router refuses auto-placed parts, so a model must give `pcbX`/`pcbY` for every part (the CAN module's placements were written by a script, pin by pin). And nothing outside the model's context remembers what the design is for, what was decided, and what is left, so a fresh context starts from the files alone. This round gives the board a placer a person and a model both use, answers about the board that fit a screen, and a project memory the model writes to and reads from in one call.

Facts: `autoplace.ts` (grid 0.5 mm, packs by block, courtyards never overlap, marks `autoPlaced`); the Studio's "Keep these positions" (`studio/src/pcb/auto-placed.ts`) writes the engine's spots as literals in one entry; the router (stage 5) treats auto-placed parts as unplaced; `circuit_summary` and `copper_summary` are compact; the 200-part benchmark board with 400 connections is the router's perf fixture; the skill `skills/copperflow/SKILL.md` tells the model to write parts and nets, not positions.

## Global constraints

The repository's constraints hold (English; one-line commits without trailers; no new dependencies; small tested modules; typecheck, test and build pass; `src/engine/` deterministic; files as LF). Nothing a person placed, locked or drew is moved. The placer's positions are written through `src/core` as one history entry, by `"ai"` when the agent asks and `"human"` from the Studio, so they are undoable, stable and visible, exactly as hand placement is; an auto-placed part that is never kept stays as today. No code from KiCad, Freerouting or other GPL tools; the published ideas (constructive placement by connectivity, simulated annealing with a deterministic schedule) are used, not their code.

## Decisions

- **Placement by connectivity.** `src/engine/pcb-place/`: (1) parts to place are the unplaced and auto-placed parts of the scope (all, a list, an instance), locked and hand-placed parts and keepouts are fixed obstacles, the board outline minus the edge clearance is the area; (2) a constructive pass: the chip with most connections first at the centre of the free area (or beside the fixed parts it connects to), then each remaining part at the spot that minimises the half-perimeter wire length of its nets to what is already placed, trying the four rotations, courtyards never overlapping, passives that hang off one chip pin placed beside that pin (decoupling capacitors nearest the supply pins they decouple: the net is a supply by pin type or name, the capacitor touches that pin's net and GND), connectors against the board edge nearest the parts they connect to, with their pins facing inward; (3) a refinement pass of pairwise swaps and single moves accepted when the total wire length drops (simulated annealing with a fixed schedule and a seeded, deterministic sequence; no `Math.random`), bounded by a time budget; (4) the result is scored: total ratsnest length, and the number of parts touching the edge clearance. Same input, same output. The 200-part benchmark places in under 5 s; the CAN module in under 300 ms.
- **Fit the board.** `fitBoard`: shrink (or grow) a rectangular outline to the placed parts' courtyards plus a margin (default 2 mm), keeping holes and locked parts inside; refused for a non-rectangular outline. Optional in `autoplace` (`fit: true`) so a model that gave no board size gets one.
- **The board in words.** `board_summary { file, detail? }`: board size and layer count, the area the courtyards use (%), one line per part (`U1 MCP2515 soic18w @(12.0, 8.5) r90 top [LOCKED]`), the ten longest ratsnest lines with their nets, parts whose courtyards overlap or leave the board, parts within the edge clearance, pours per layer, unrouted count — at most about 60 lines, the rest behind `detail: "full"`. `check_circuit` already lists the placement findings; `board_summary` is the model's eyes.
- **The project remembers.** `PROJECT.md` at the project root, owned by the model and the person together: Intent (one paragraph), Blocks (one line each: name, what it does, status), Decisions (dated one-liners), Open (what is left). `note_decision { file?, text }` appends a dated line under Decisions; `set_project { intent?, blocks?, open? }` rewrites those sections (one history entry each, as a file edit). `project_status { }` answers in a screenful: the Intent, the Blocks table, the last five Decisions, Open, then per circuit file the counts (parts, nets, unplaced, unrouted, errors, warnings) and the last three changes from history — the first call a fresh context makes. The Studio shows `PROJECT.md` in the left panel's Project tab (read-only text; edits through the file).
- **The design workflow skill.** `SKILL.md` gains the order the maintainer named: read `project_status`; write Intent; blocks first (sub-sheets, one per block), design each block, clone channels as instances, choose parts (library, generated package, wizard, import), ask the person before the PCB, place block by block (`autoplace` with `parts` or `instance`), then the board shape and connectors (`fit`), fine tuning, `autoroute`, `check_circuit`, export. Each step says which tool and what the answer looks like, so the model never reads a file to find out.

## Task 1: the placer

- `src/engine/pcb-place/` (`scope.ts` what moves and what is fixed, `constructive.ts`, `refine.ts`, `score.ts`, `fit-board.ts`, `index.ts` → `placeBoard(design, options): Placement`) returning positions and rotations per part plus the score; pure and deterministic; `autoplace.ts` keeps packing parts nobody placed yet (the build does not run the placer).
- Tests: a chip with four decoupling capacitors lands with each capacitor beside its supply pin; a connector lands on the edge nearest its chip with pins inward; no courtyard overlaps, no part outside the board, locked parts and keepouts untouched; total wire length after placement is lower than the column packing on the CAN module and on the benchmark; the refinement never raises the score; determinism (twice the same); `fitBoard` on the CAN module; the perf bounds (`npm run test:perf`).

## Task 2: the Studio and the agent place

- Server: `POST /api/place { file, scope, fit? }` in the router's worker pattern (progress through live events, cancel, discard on content-hash change), the result written through the core as `set_props` `pcbX`/`pcbY`/`pcbRotation` in one entry. Studio: Place → **Autoplace** (all unplaced), Autoplace selection, Autoplace instance, Layout → Fit board; a progress line with Cancel; undo removes the run. MCP: `autoplace { file, parts?, instance?, fit?, budgetSeconds? }` answering "Placed 12 parts; wire length 184 mm (was 412); board 42 × 28 mm; 0 overlaps" and `fit_board { file, margin? }`.
- `new_circuit` with `place: true` (default true) runs the placer after writing, so a netlist becomes a placed board in one call; `board` optional (fit when absent).
- Tests: the route and event shapes, the commands, the written edits, one history entry, locks respected, the tool shapes and answers.

## Task 3: the board in words and the project memory

- `src/mcp/board-summary.ts` (the format above, tested for line counts on the demo and CAN boards); `src/core/project.ts` (read, append and rewrite `PROJECT.md` sections, creating the file with empty sections when missing; one history entry per change, `by` as the caller says); `project_status`, `note_decision`, `set_project` tools; the Studio's Project tab.
- Tests: the summary on three boards (small, CAN, benchmark), `PROJECT.md` round trips (append under Decisions keeps the other sections byte for byte), `project_status` on a project with two circuits, the tool shapes.

## Task 4: the skill

- `SKILL.md`: "Every task" starts with `project_status`; the design workflow section as decided; `references/design-workflow.md` with one worked example (a two-channel sensor board: blocks, instances, part choices, the approval question, the placement order) written as the sequence of tool calls and the answers they give. INSTRUCTIONS of the MCP server shortened to point at the skill.
- Tests: the skill files are under 200 lines each and mention every tool the server registers (a test lists the registered tools and greps the skill).

## Task 5: proof (controller)

A fresh agent on a cheap model is given only the skill and the MCP server on an empty project and a one-paragraph brief (the CAN module: MCP2515 + TJA1051 + crystal + decoupling, SPI header, CAN screw terminal, 3.3 V). It must reach a routed board with 0 errors and an export. Measured: the number of tool calls and the total characters of tool answers (the context the design costs); the target is under 25 calls and under 40 000 characters. `project_status` after the run shows the Intent, the block and the decisions it noted. The maintainer opens the board in the Studio and judges the placement by eye.
